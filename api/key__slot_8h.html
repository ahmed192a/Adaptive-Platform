Detailed Description

ara::crypto key-slot facade: KeySlotPrototype / KeyStorageProvider.

Modelled on the SWS Cryptography KeySlot concept. A slot is declared with a prototype (algorithm, allowed usage, exportable, persistent) and then holds at most one key. Key material never leaves the provider except through Export() on an exportable slot; all cryptographic operations are performed by name.

  • Usage is enforced per slot: a sign-only key cannot verify, a MAC-only key cannot encrypt, and so on (kUsageViolation).
  • Persistent slots are stored through ara::per::KeyValueStorage as AES-256-GCM(wrappingKey) blobs. The slot name, algorithm, usage and exportable flag are bound as AAD, so a blob that is edited, copied into another slot, or loaded under a different prototype fails authentication and the slot is reported as kCorrupted (never silently used).
  • A volatile provider (no storage) only accepts non-persistent slots.

The wrapping key should come from a hardware/secure source on a real ECU; here the caller supplies it. All methods are thread safe and exception free.

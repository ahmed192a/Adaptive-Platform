ara::diag - conformance to AUTOSAR AP Diagnostics

Verification basis (read this first)

  • Target release: R25-11. The R25-11 SWS PDF could not be fetched from the build environment (host not allow-listed), and the R24-11 copy that could be reached returned only its front matter and table of contents.
  • So requirement IDs and numeric values are not verified and none are quoted here. What is confirmed (R24-11 table of contents) is the class and function names: Conversation, GenericUDSService (HandleMessage, Offer, StopOffer), GenericDataIdentifier, DataTransfer*, GenericRoutine (Offer, Start, Stop, RequestResults, StopOffer), Monitor (Offer, ReportMonitorAction, StopOffer), DTCInformation, Event, and the error enumerations DiagErrc, DiagOfferErrc, DiagReportingErrc, DiagUdsNrcErrc.
  • Fallback to earlier releases: R22-11 (and the nearest reachable releases) SWS PDFs are also not on the allow-list, and third-party Doxygen mirrors only list names without values. The gap work below therefore follows ISO 14229-1 for service behaviour and the confirmed ara::diag class names for the API; no SWS requirement text or numeric DiagErrc value was available to quote. Scope changes between releases are small for this cluster.
  • UDS behaviour is checked against ISO 14229-1 knowledge, which is what the SWS defers to; status "Implemented" below means "behaves as ISO 14229-1 describes and is covered by a test", not "SWS-certified".

What ara::diag is today

DiagnosticServer is a transport-independent UDS engine (call Dispatch(request, Addressing) from DoIP/ISO-TP). diag_facade.h adds pragmatic counterparts of the SWS classes (Conversation, GenericUDSService, GenericRoutine, GenericDataIdentifier, Monitor) on top of it, using ara::core::Result and byte vectors rather than the SWS Future/OperationOutput signatures. App/demo/uds_tester drives the whole server through a scripted session (see the demo section).

0x85 ControlDTCSetting Implemented on/off freezes event-memory updates

0x23 / 0x3D Read/WriteMemoryByAddress Implemented addressAndLengthFormatIdentifier parsing, registered MemoryRegions, session + security gating

SWS API surface

SWS element Status Notes
Conversation, ConversationIdentifierType Partial diag_facade.h Conversation wraps a server; signatures are pragmatic, not SWS Future-based
GenericUDSService (Offer/StopOffer/HandleMessage) Partial Offer/StopOffer over RegisterService/UnregisterService; byte-vector signatures
GenericDataIdentifier / data-transfer classes Partial read/write DIDs plus SetTransferHandler for 0x34-0x37; no SWS DataTransfer* class hierarchy
GenericRoutine Partial Offer/StopOffer lifecycle, start/stop/results; no routine-specific serialization
Monitor, Event, DTCInformation Partial Monitor with counter debounce (failed/passed thresholds, freeze, reset, fault detection counter -128..127), occurrence counter, snapshot and extended data; no time-based debouncing or aging
DiagErrc enumerators Partial names kAlreadyOffered/kConflict/kNotOffered/... are used; numeric values and domain id are implementation choices (Unverified); DiagOfferErrc, DiagReportingErrc, DiagUdsNrcErrc do not exist yet
Persistent DTC memory (via ara::per) Implemented MakePerDtcStorage(kvs) saves after every change and reloads on start (per_dtc_storage.h)

Remaining gaps

  1. DiagOfferErrc, DiagReportingErrc, DiagUdsNrcErrc are not created: their enumerators and values could not be verified and inventing them would be misleading. DiagErrc numeric values and domain id stay Unverified.
  2. SIDs 0x2A, 0x2C, 0x38, 0x86, 0x87 and ReadDTCInformation sub-functions beyond the six above (severity, mirror memory, user-defined memory) are not implemented.
  3. DTC aging and debouncing state are not persisted; only status, occurrence counter, snapshots and extended data are.
  4. The facade uses ara::core::Result and byte vectors instead of the SWS Future, OperationOutput and MetaInfo types.
  5. No ISO-TP / DoIP transport: Dispatch is the integration point.

Known deviations

  1. Status-of-DTC availability mask is fixed (0x2B).
  2. Built-in SIDs cannot be overridden through RegisterService (returns kAlreadyOffered); use RestrictBuiltinService to change which sessions may call one.

Demo

App/demo/uds_tester builds a small body-control ECU on top of the server and a tester that runs 35 checks: default session, identification DIDs, functional TesterPresent, extended session and write, security access (wrong key, then right key), routine, DTC count/list/snapshot/extended data/clear, memory read/write, firmware download with a block sequence error, communication control and reset. Run uds_tester for the trace, or uds_tester --repl to type hex requests (f 3E 80 = functional, wait 6000 advances the S3 clock).

Tests

Testing/diag: ara_diag_ut (existing 24 tests plus 21 gap tests: functional addressing, partial multi-DID, session restriction, ECUReset 4/5, CommunicationControl, memory access, download/upload with counter and session cancel, responsePending, DTC snapshot/extended/occurrence, group clear, persistent restart, codec, facade, monitor debounce) and uds_tester_ut (4 tests: the scripted session, hex parsing/description, S3 timeout).

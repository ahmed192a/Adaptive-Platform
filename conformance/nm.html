ara::nm - conformance to AUTOSAR AP R25-11 (SWS_NetworkManagement)

Source: AUTOSAR_AP_SWS_NetworkManagement.pdf, R25-11 (requirement prefix SWS_ANM_). Status values: Implemented, Partial, Missing, Deviation (implemented differently), Unverified (the retrievable SWS text does not settle it - nothing is guessed). Every row below is covered by Testing/nm unless noted.

Architecture note (the main deviation, now fixed)

The SWS defines ara::nm::NetworkHandle as the State Management facing API with only two states, kNoCom / kFullCom (SWS_ANM_01000, 01358). The first implementation used that name for the NM state-machine engine. The engine is now ara::nm::NmChannel (nm_channel.h), and ara::nm::NetworkHandle (network_handle.h) is the spec facade on top of it. A handle is bound to a channel through its port InstanceSpecifier: NetworkManager::BindPort(specifier, network). An unbound handle reports kServiceNotAvailable, like a lost daemon connection.

Known gaps (not implemented)

NM coordinator functions; bus drivers (the engine only produces/consumes PDU objects); the exact CBV bit positions and the ara::core executor concept stay Unverified (see above). Nothing else is open.

Release notes for this gap-closing pass

R25-11 text was tried first; where a requirement id could not be retrieved the earlier-release extract used by the original audit applies (the NM state machine and PDU rules are unchanged between releases per the project owner's guidance). No requirement id above was invented. Demo: App/demo/nm_bus_monitor (3 ECUs, partial networks, state timeline).

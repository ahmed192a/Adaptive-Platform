ara::tsync - conformance to AUTOSAR AP R25-11 (SWS_TimeSynchronization)

Source: AUTOSAR_AP_SWS_TimeSynchronization.pdf, R25-11 (prefix SWS_TS_). Important limitation: the retrievable R25-11 text contains the functional specification and the class/method names, but not the section 8 API tables. Signatures, callback types and numeric error values below come from the R23-11 text where it was readable (marked R23-11) and are otherwise Unverified. Nothing is invented. Status values: Implemented, Partial, Missing, Deviation, Unverified.

Layering

  • TimeBaseResource / TimeBaseProvider (time_base.h) - the time base engine (clock extrapolation, slew/step, timeout). Not part of the SWS.
  • SynchronizedTimeBaseConsumer, SynchronizedTimeBaseProvider, SynchronizedTimeBaseStatus (synchronized_time_base.h) - the SWS API. Bound to a time base by InstanceSpecifier through TimeBaseRegistry::Bind. Unbound -> kDaemonConnectionLost / neutral values.

Gap-closing pass

New: TsyncErrc::kTimeCannotSet = 8 (the numeric value is Unverified; the name and requirement ids 01107/01207 come from R22-11/R25-11). The error-domain id remains 0x8000000000000502, an implementation choice, because the normative id is not retrievable. Still open: security events, diagnostics and the StbM mapping (rows above). Where R25-11 text was unavailable, R22-11 was used; the two releases agree on the cited requirements. Demo: App/demo/time_sync_clock (provider/consumer, slew vs step, rate flags, timeout).
